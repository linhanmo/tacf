## §4 TACF 四阶段训练与概率校准协议 (正式规范)

> 该协议来自 2026-09-24 的方向性修正 (用户 request 11)，取代此前所有
> composite coverage / 混合 monitor 策略。代码实现入口：
> `src/experiments/main.py` 的 `cfg_s1/cfg_s2/cfg_s3/cfg_s4`。

### 4.1 训练目标分层（先把点估计做好，再谈校准）

```
S1 / S2 ——————→ S3     ————————→ S4
MSE 驱动        NLL 主驱动         NLL 主驱动
(μ 预训练)      + ECE + r_k 分布   + CRPS + ECE
                                ↓ post-hoc
                         temperature_scale_nll
                         σ' = T · σ   (最小化 VAL NLL)
```

| 阶段 | Best Epoch 监控 | 主损失 | 辅助损失 / 指标 | 最终判定 |
| --- | --- | --- | --- | --- |
| S1 Pretrain | **val_mse** (min) | **MSE (λ=1.0)** | NLL (λ=0.05, 仅保留 σ 非零) | val_mse 最小 |
| S2 Consensus | **val_mse** (min) | **MSE (λ=1.0)** + σ_reg (0.02) | NLL (0.10), Consensus_reg, LR warm (5 ep ×0.1) | val_mse 最小 |
| S3 Aggregator | **val_nll** (min) | **Gaussian NLL (λ=1.0)** | MSE (0.2), **ECE (0.5)**, **r_k 分布惩罚 (0.2)**, σ_reg (0.05) | val_nll 最小 + ECE↓ + r_k histogram near 10%±5% |
| **S4 End2End** | 训练 best = **val_nll**<br>**Final best = Val NLL (σ×T 之后)** | **Gaussian NLL (λ=1.0)** | MSE (0.2), **ECE (0.3)**, **CRPS (0.5)**<br>ECE, 50%/90%/95% coverage, Width | **温度缩放后 val_nll 最小** + ECE↓ + 50%/90% coverage 接近理论分位 |

### 4.2 S4 Post-hoc 温度缩放（Regression Temperature Scaling）

单参数 `σ' = T · σ`，是严格的 proper-scaling，不改变预测均值 μ，只校准不牺牲 MSE。

**流程（main.py S4 runner 之后）**
1. 取 S4 best.pt → 在 val_loader 上 `_evaluate` 得到 `(val_mus, val_sigmas, val_ys)`
2. `temperature_scale_nll(mus, sigmas, ys)`：
   - **粗扫**：T ∈ `[0.1, 5.0]` 41 点 grid，取 nll 最小的 T₀
   - **精修**：L-BFGS 对 `log T` 局部优化（保证 T>0），最多 80 步
   - **边界保护**：clamp T ∈ [0.1, 5.0]，极端情况（σ 塌缩到 0 导致需要 T>50）**直接失败提示而非硬救**
3. `cfg.eval_temperature = T_final` → 重新 `_evaluate(val_loader)` 与 `_evaluate(test_loader)`，得到 post-T val/test metrics
4. 写 `results.json`：`stage4.temperature_scaling = {T, nll_before, nll_after, status, N_samples}`，及 `scaled_val_metrics / scaled_test_metrics`

### 4.3 RMSE 软弃用声明

- **保留**：`MetricsResult.rmse` / `LoggedValues.val_rmse / test_rmse` 字段仍然存在（兼容历史 CSV / 下游分析脚本）。
- **移除高亮引用**：① Trainer 的 train/val/test epoch 打印；② best-epoch 决策；③ 所有汇报级脚本的辅指标位。S4 的 probabilistic secondary 指标位由 **CRPS (closed-form Gaussian)** 正式占据。
- **原因**：RMSE 是点估计指标，在 multi-target regression / 非高斯 y 分布数据集（traffic, electricity）上不具备 proper scoring 性质，用它做 probabilistic 模型选 best epoch 属于通用时间序列文献的不专业行为。

### 4.4 σ 数值稳定性保障

- gaussian_nll / compute_metrics / temperature_scale 三处 σ 数值 floor **统一到 1e-3**；
- σ_reg 凸正则的 log 项使用更小 floor（1e-5），**不与数值 floor 共享 clamp**，保证 σ<1e-3 时 σ_reg 的正梯度仍能把 σ 推大；
- 所有 stage runner `_loss_fn` 的累加器必须是 `torch.zeros((), device=y.device, dtype=torch.float32)`，loss 在 f32 下累加后末步 `.to(dtype=y.dtype)` cast 回模型 dtype，**禁止 `float + CUDA f16 tensor`** 的混合加法（会触发 PyTorch 内部 `CUDAGuardImpl.h:28` ASSERT）。
